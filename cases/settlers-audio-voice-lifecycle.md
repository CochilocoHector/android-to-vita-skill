# 案例：音频 voice 生命周期（音效变慢/沙哑）

> 状态：**◐ 已实现未验证** —— v0.61 已构建，尚未实机确认。

## 现象

音效可以播放，但海鸥叫声低沉、沙哑、明显变慢。

## 初始假设

- OGG 解码帧数错误（帧/样本混淆）
- 重采样 step 算反或重复重采样
- 输出端口采样率不是 48000

## 静态证据

1. **解码正确**：解码帧数与 OGG granule 完全一致

   | 文件 | granule | 解码 | 时长 |
   |---|---|---|---|
   | 0001.ogg | 12864 @22050 | 12864 | 0.583s |
   | 0056.ogg | 4068 @22050 | 4068 | 0.184s |
   | 0155.ogg | 363245 @44100 | 363245 | 8.237s |

2. **重采样正确**：`step = rate/48000`；22050 → 0.459375；
   12864 源帧 → 28026 输出帧 @48k = 0.5839s，与原始一致

3. **端口配置正确**：VitaSDK 头文件——`len` 为 PCM 帧、MAIN 必须 48000、
   交错 16-bit；`buf[512*2]` 匹配

4. **原版语义**：Java `playSoundBig` 使用 `d[id]` 单个 MediaPlayer，
   对正在播放的实例重复 `start()` 是空操作（[DEX] smali）

5. **兼容层问题**：每次调用都新建 voice 并从 `pos=0` 开始（[SRC]）；
   日志中同一 id 多次带不同音量调用（`44: 50→77→100`、`57: 50→100`）（[LOG]）

## 排除的错误假设

| 假设 | 排除依据 |
|---|---|
| 解码帧数错 | granule 与解码帧数逐一吻合 |
| 重采样算错 | 时长与音高保持 |
| 端口采样率错 | 与 VitaSDK 文档一致 |
| 解码缓存导致半速 | 缓存命中返回同一 sample，不影响 step |

## 根因

同一音效 id 被重复调用时，兼容层叠加多份并从 0 重启；
原版每个 id 只有一个播放器实例，重复调用不重启。

## 最小修复

按 id 管理 voice：

- 同 id 播放中：只更新 gain/loop，不重置位置
- 同 id 结束后：允许重新开始
- 不同 id 仍并发（8 槽位）
- 满时丢弃并告警，不再顶掉 voice 0
- 停止/播完清理 `active/smp/id`

## 实机验证

☐ **待验证**（v0.61）：

- 海鸥音色是否恢复

## 可迁移的方法

1. 先核对"解码结果 vs 容器声明的样本数"，排除解码层
2. 再验算 step 与输出时长，排除重采样层
3. 最后对照原版播放器的**实例模型**（每 id 一个 vs 每次一个）
