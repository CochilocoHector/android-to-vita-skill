# 案例：device_type 被重置（整屏黑）

## 现象

启动后画面全黑，但日志显示纹理已上传、GL 无错误。

## 初始假设

- 资源缺失或路径错误
- 纹理格式不被支持

## 静态证据

- 三个解码器由同一全局分派（[ASM]）：

  ```
  0/2/4 → loadATCTexture
  1/3   → loadPVRTexture
  5     → loadDXTTexture
  ```

- 该全局在游戏初始化流程中被写入 0（[ASM]）
- 数据文件是 DXT5（[BYTES] `BTEXdxtr`），不是 ATC

## 排除的错误假设

| 假设 | 排除依据 |
|---|---|
| 资源缺失 | 文件存在，`ITEXTEX`/上传日志都有 |
| vitaGL 不支持纹理 | 地形用同样 GL 调用正常 |
| 尺寸错误 | 上传尺寸与文件头一致 |

## 根因

游戏把 `device_type` 改回 0，于是 DXT 数据交给 ATC 解码器，输出无效。

## 最小修复

每帧把该全局写回 5（加载器主循环，一行）。

## 实机验证

✅ 地形与精灵显示正常。

## 可迁移的方法

1. 找"同一份数据被不同解码器处理"的分派全局
2. 确认游戏是否在初始化时重置它
3. 用每帧钉住值 + 日志打印来验证
