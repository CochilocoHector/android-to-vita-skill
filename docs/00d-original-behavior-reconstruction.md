# 00d · 原版行为还原与兼容层规格

## 1. 目标

把反编译结果写成一份**可以直接照着实现的规格**，而不是散落的笔记。
规格写不出来，说明还没看懂。

## 2. 规格模板

```markdown
## 接口：playSoundBig
- 签名：(int id, float volume, int loop) -> void      [DEX]
- 调用方：C++ CSoundManager::PlaySoundFX               [ASM]
- 行为：
  1. 若 d[id]==null 或 a[id]==7 → loadSoundBig(id)
  2. n = volume / 70.0
  3. setVolume(n,n); setLooping(loop==1); start(); a[id]=6
- 资源：Snd/ + getSoundFileName(id)                    [DEX]
- 生命周期：每 id 一个实例；重复 start 为空操作         [DEX]
- 失败处理：try/catch 静默                              [DEX]
```

## 3. 必须还原的六类信息

| 类别 | 问题 |
|---|---|
| 入口 | 哪个函数被谁调用？ |
| 参数 | 每个参数的类型、单位、取值范围 |
| 分支 | 所有 early return / 特殊值处理 |
| 状态 | 读写哪些全局/对象字段，迁移条件 |
| 资源 | 文件名规则、打开方式、失败行为 |
| 生命周期 | 实例何时创建/复用/销毁 |

## 4. 从反编译到规格的推导

```
① 列出函数的所有比较与常量
② 把所有 early return 写成前置条件
③ 把字符串拼接写成文件名生成函数
④ 把数组索引写成"每 id 一个实例"
⑤ 把状态常量写成状态机
⑥ 用一句话描述"重复调用会发生什么"
```

第 ⑥ 步是移植正确性的关键。

## 5. 兼容层差异表

```markdown
| 行为 | 原版 | 兼容层 | 状态 |
|---|---|---|---|
| 实例数量 | 每 id 1 个 | 每调用 1 个 | ❌ |
| 重复调用 | start() 空操作 | 从 0 重启 | ❌ |
| 音量刻度 | /70 | /70 | ✅ |
```

## 6. 最小实现原则

1. 只实现差异表中 ❌ 的项
2. 不改动已经 ✅ 的项
3. 不顺便"优化"别的行为
4. 实现前把规格写进项目知识库

## 7. 验证设计

静态还原的每个结论，配一个最小验证：

| 结论 | 验证 |
|---|---|
| 该方法被调用 | 入口日志（含 caller） |
| 参数值 | 按签名解析并打印 |
| 走了哪个分支 | 观测后续调用是否发生 |
| 实例数量 | 播放中统计同 id voice 数 |
| 资源映射 | 打开日志 + 文件是否存在 |

## 8. 何时停止静态分析

出现以下情况就转向动态实验：

- 需要知道运行时才存在的值（指针、句柄、配置）
- 调用经 vtable/函数指针，静态无法确定目标
- 数据来自网络/存档/加密资源

动态实验要求：**一个探针、一次运行、一个明确判据**。

## 9. 成功判定

- 静态规格 ✅
- 实机现象消失 ✅
- 无回归（相关功能仍正常）✅

三者缺一，不得标记为"成功案例"。
